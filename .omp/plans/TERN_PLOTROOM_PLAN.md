# Tern Plotroom

## Context
Build **Tern Plotroom**, a native Tern SDK plugin whose first tool is a live GitHub PR queue. It must support editable saved filters, opening a PR in a Browser block, and creating/opening a PR worktree in a new tab, using existing `gh` authentication. The user explicitly prefers existing local clones and the cwd of the pane/tab launching Plotroom as the repository when possible. Explore additional SDK integrations for the eventual agentic Jira/GitHub/Linear/GitLab suite; those integrations are recommendations, not part of the implementation authorized here.

## Approach

### 1. Open a native PR block with the launching directory
Create `plugin.toml` with `schema = 1`, `id = "plotroom"`, `name = "Tern Plotroom"`, `version = "0.1.0"`, `host = "host.luau"`, `window = "window.luau"`, `styles = ["plotroom.css"]`, and one `[[blocks]]` entry `id = "prs"`, `title = "Plotroom · GitHub PRs"`, `palette = false`. Define it with `tern.block.define("prs", ...)` in `host.luau`.

Register `tern.command({id="open", title="Plotroom: Open GitHub PRs", ...})` in `window.luau`; its action is `plugin.plotroom.open`. Capture `cx.session:focused()` and that pane's `cwd` before opening anything. Use `cx.layout:split(sourcePane,"right",{block="plotroom.prs",cwd=sourceCwd,args={sourceCwd}})`; without a focused pane use `cx.layout:new_tab({block="plotroom.prs"})`. The host resolves launch directory in order: restored `launchCwd`, `args[1]`, `cx.cwd`; a missing directory leaves browsing usable and requires a local repository path for worktrees. Preserve the captured directory even if the user later changes tabs or the source shell changes cwd.

Expose the captured directory as a read-only `ui.node("text",{key="context",text=launchCwd or "",role="repo-context"})` at `main.context`; window actions read that exact node instead of consulting the currently focused shell. Before opening or acting, use `cx.hosts:list()` and its `panes` membership to identify the source host; only `kind="local"` permits the local worktree path. For tab completion, resolve `cx.session:tab_of(sourcePane)`, find that tab's `session` in `cx.session:tabs()`, confirm it still exists, then `cx.sessions:switch(sessionId)` before `new_tab`.

Keep responsibilities concrete, without a provider registry/framework:
- `host.luau`: native block, filter editing, persisted filter/mapping writes, search refresh lifecycle.
- `window.luau`: palette actions, direct link routes, embedded Browser placement and worktree-tab completion.
- `github.luau`: existing-auth `gh` runner and PR search/page normalization; shared by host and window.
- `worktree.luau`: asynchronous Git resolution/fetch/worktree flow used by the window entry.
- `process.luau`: one shared PATH-aware process runner for gh and Git; there is no existing repository helper, and the example's fixed-path fallback does not cover the user's installation.
- `input.luau`: the small reusable single-line editing model needed by filter name/query/path fields; no equivalent is present in this empty repository or the examined SDK examples.
- `plotroom.css`: scoped spacing/row layout only, built-in colors and typography.

Use `--!strict` and the SDK global `tern`. API declarations generated from the installed runtime, not npm/React/webview dependencies, are the typing contract. Do not introduce Jira/Linear/GitLab interfaces before a second real provider exists.

### 2. Fetch and reconcile complete PR search snapshots using gh
In `github.luau`, expose `search(query: string, shouldContinue: () -> boolean, done: (result: SearchResult?, problem: Problem?) -> ()): ()` and `pr(repo: string, number: number, done: (result: any?, problem: Problem?, cx: WindowCx?) -> ()): ()`; the latter forwards the fresh process-callback context for worktree continuations. `Problem` is `{kind: "missing" | "auth" | "rate-limit" | "failed" | "superseded", message: string}`. `SearchResult` contains `prs`, `total`, `complete`; each normalized PR has `key`, `repo`, `number`, `title`, `url`, `author`, `state`, `draft`, `updated`. Identity is lowercase `owner/repo#number`; preserve display spelling.

Use the shared PATH-aware runner below for every gh invocation; remove the Review Queue example's entire fixed executable candidate list. Execute all gh/Git operations as argv arrays via `tern.process.run`, not shell command strings. Use `GH_PROMPT_DISABLED=1`, `GH_NO_UPDATE_NOTIFIER=1`, `NO_COLOR=1`; explicitly pass `--hostname github.com`. Do not invoke `gh auth token`, switch accounts, store credentials, or implement an alternate login flow. Report missing CLI, unavailable authentication, timeout, permission/validation errors and malformed JSON in the block with Retry and the relevant manual `gh auth login`/installation guidance.

**PATH resolution contract (`process.luau`).** Export `run(argv: {string}, opts: ProcessOptions, done: (result: ProcessResult?, problem: string?, cx: WindowCx?) -> ()): ()` and `reset(): ()`. `github.luau` and `worktree.luau` both use this runner; do not maintain separate executable-resolution implementations.
1. First spawn the bare executable name (`"gh"` or `"git"`) with the inherited PATH. The SDK already performs PATH lookup, so do not reimplement `which`, manually scan directories, or hard-code mise/Homebrew/Nix/asdf installation paths.
2. If spawning raises, recover the user's shell PATH once and retry that same argv directly with `opts.env.PATH` set to the recovered value. This handles a Dock/launchd-started daemon whose PATH lacks interactive-shell tool-manager entries. Do not retry a process that actually started and returned a nonzero status: authentication/API/Git failures are not discovery failures.
3. Recover PATH asynchronously using `tern.getenv("SHELL")`, requiring a nonblank absolute executable path; launch `{shell, "-l", "-i", "-c", script}` from HOME (or the plugin directory if HOME is absent), with a 5-second timeout. Use exactly this fixed script: `printf '\\0PLOTROOM_PATH\\0'; /usr/bin/printenv PATH; printf '\\0PLOTROOM_END\\0'`. The standard `/usr/bin/printenv` was verified present on the target Mac. Login plus interactive startup is intentional: tool managers may modify PATH in `.zshrc`, not just login profiles. This executes the operator's normal shell startup files, never PR code or query-derived commands. No user query, path, repository name or CLI arguments are interpolated into the probe.
4. Extract only bytes between those NUL-delimited markers; remove the single trailing newline added by printenv, not whitespace in individual PATH entries. Require successful exit and a nonempty NUL-free PATH. Ignore startup banners outside the markers. Do not read/dump the whole environment, source guessed shell files, or assume `~/.local/bin` is the installation directory. Missing SHELL, unsupported shell invocation, timeout, malformed output or a second spawn failure produces one actionable error naming the failed program and explaining that it must be available in the configured shell's PATH; do not fall back to guessed install locations.
5. Cache the recovered PATH in memory per Luau VM, not executable version paths or KV. Apply it to gh/Git and their child processes so shims can find their dependencies. Coalesce simultaneous recovery requests and use fresh process/timer callback contexts; asynchronous callbacks must never retain a window `cx`. Deliver initial synchronous spawn/probe-setup errors through a zero-delay timer callback when a fresh context is needed. `reset()` clears recovery state; explicit Retry invokes it, permitting corrected shell configuration to be discovered without restarting Tern. Do not run a login shell on each poll or persist the recovered PATH.

For every refresh, fetch pages sequentially with:

```text
gh api --hostname github.com --method GET search/issues
  -f q=<saved-query plus is:pr> -f per_page=100 -f page=<1-based-page>
  -f sort=updated -f order=desc
  --jq '{total_count,incomplete_results,items:[.items[]|{id,number,title,html_url,repository_url,user:{login:.user.login},state,draft,updated_at,pull_request}]}'
```

Each `-f` value is one argv element. Preserve the user's query text, including quotes/negative qualifiers; do not split/rewrite it with a homegrown query parser. Require nonblank queries and append `is:pr`; reject any returned non-PR item instead of displaying issues. Treat API validation errors as errors, not empty success. Validate PR URLs as `https://github.com/<owner>/<repo>/pull/<positive-integer>` before using them, and derive repository identity from that canonical shape. Titles and author names are plain text, never HTML or executable payloads. Omit bodies from stdout to avoid unnecessary data and the SDK's 16 MiB process-output ceiling.

Timeout each CLI call after 30 seconds. Accumulate pages off-screen, deduplicate by identity, sort updated descending with identity as a deterministic tie-breaker, and swap the list only after all pages succeed. Successful empty results clear the list. A later-page failure retains the last complete snapshot and shows it as stale. `incomplete_results=true` or `total_count>1000` produces a prominent partial-results warning, including loaded/total and “Narrow this filter”; never label it all matches. GitHub imposes the 1,000-result search cap and indexing delay; no smaller plugin-imposed limit. Do not perform speculative date-sharding to bypass search semantics.

Refresh immediately on launch, applying a query, selecting a filter and explicit Refresh, then 60 seconds after each finished attempt. Only poll the selected filter of each live block, not every saved filter. Keep one request chain per block. Increment a generation on every applied-query change, including editing an existing filter id, and on filter switches. Pass `shouldContinue` capturing that generation, exact query text, and state lifetime; check it before each page and after each response. If false, stop paging and complete with `kind="superseded"` without a visible error, then run the latest queued query immediately. An already-running process can finish, but abandoned remaining pages must not run. Preserve selection by PR key across refreshes; removed selections fall back to the first result. Key in-memory last-success snapshots by exact applied query text, not filter id, so editing a filter cannot relabel old results with a new query.

Reuse Review Queue's lifetime checks in every timer/process completion: the captured state must still be `running[cx.pane]`, and the pane must still exist. No block-close hook exists; retire dead state and cancel its timer on the next callback. Never persist timers or process state. For HTTP 403 rate-limit errors or 429, show the error and wait five minutes before automatic retry (ordinary errors retry on the normal interval); manual Retry remains available. Use `cx:render()` only after background state changes. SDK callbacks are asynchronous; never block a host or window handler waiting on a process.

### 3. Edit and persist multiple filters using native controls
Use `tern.kv` with host-only writes to two keys:
- `filters`: `{version=1,nextId=<integer>,items={{id="f1",name="My PRs",query="is:open author:@me"},...}}`.
- `repos`: map from lowercase `github.com/owner/repo` to an absolute local checkout path.

Seed filters only when the key is absent: **My PRs** (`is:open author:@me`) and **Review requested** (`is:open review-requested:@me`). Do not overwrite malformed storage or replace an intentionally empty filter list. Wrap storage I/O in `pcall`; show failures and keep drafts intact. A read error permits browsing with transient state but disables successful-looking Save until storage is writable. Persist a pane's `{version=1,launchCwd,activeFilterId}` via `BlockDef.save`; do not persist fetched private PR data. When a saved active id no longer exists, select the first saved filter; with no filters display “Add a filter”.

Render a compact header, scrollable saved-filter list (`key="filters"`, `selected="main.filters."..activeId`, `max={lines=3}`), the applied query, and New/Edit/Delete/Refresh controls. Do not use `tabs`: SDK tabs clip instead of scrolling. A `select` event with `id="main.filters"` switches filters; Tab moves keyboard focus between the filter list, PR list and form controls, and arrows act on the focused list. New/Edit reveals labelled `input` nodes for name and query with Save/Cancel. Trim names and query edges, require both nonblank, permit duplicate names (ids determine identity). Save updates the selected item or allocates `f<nextId>` and selects it. Cancel changes nothing. Delete requires an inline confirmation, removes only that filter, and chooses the next available filter. Keep drafts independent of applied values. Filter switching cancels an unfinished draft rather than saving it. After a host filter write, update other live Plotroom states in that VM; reread storage on selection and refresh so restored panes see changes.

The result list uses `ui.list`/`item` with stable PR keys and `max={lines=...}` from the Review Queue example. **Render 100 results per UI page**, with Previous/Next buttons and “101–200 of N” text; still fetch and retain every API page up to GitHub's cap. SDK lists automatically virtualize above 200 rows and virtual rows do not wire custom links/actions, so never put all 1,000 rows in one list and never reduce the fetched results to work around this. Up/down navigates across the full result array and changes the UI page as needed; preserve the selected key and recompute its page after refresh. Show repository/number, title, author, open/closed/merged-or-draft status where returned, and updated timestamp. Draft/state text accompanies color. Native text nodes and badges provide the toolbar and selected-PR actions in the dock. No CI/review-status N+1 API requests are needed. Expose the selected PR's Browser and Worktree action links as stable dock nodes `dock.open-pr` and `dock.worktree` for palette accessibility. Each row is directly clickable to open the PR, and the dock Worktree action acts on the selected row.

Give the list key `prs` (id `main.prs`) and each row its normalized PR key. When a validated window-local row route runs, send `cx.session:event(sourcePane,{ev="select",id="main.prs",item="main.prs."..prKey})` before opening; this keeps mouse-selected and keyboard-selected dock actions consistent without broadcasting the open.

Implement `input.luau` as a Unicode-safe single-line model: insertion, paste (replace CR/LF with spaces), left/right, Home/End, Backspace/Delete, Shift selection, select-all, copy/cut through `cx:copy`, and bounded local undo. Store offsets at UTF-8 codepoint boundaries and convert to UTF-16 units for SDK `cursor`/`anchor`. Tab cycles visible fields/actions, Enter saves the form, Escape cancels. Handle `focus` with `cx:frame({{"focus",nodeId}})`. The published host guide says native edit events are not enabled; newer SDK source declares `BlockDef.features`. Use a fixed compatibility rule: if the generated installed declarations expose `features`, set `features={"edit","undo"}` and also handle UTF-16 `edit`/`undo` events (ignore stale `len`); otherwise omit features and use the same key-driven model. Do not depend exclusively on native editing, which users can disable.

CSS selectors must begin under `[data-surface="plugin.plotroom.prs"]` for main/dock/layer. Use native spacing, fonts and semantic tokens (`--t1`…`--t4`, `--accent`, `--ok`, `--warn`, `--bad`, surface variables), not fixed light/dark palettes. Labels and focus/selection indicators must remain visible in narrow panes and both themes. Do not globally restyle Tern.

### 4. Route PR clicks to exactly one embedded Browser block
Use **native window-handled open actions**, not host `cx:open`: a row/node has `p.href="plotroom://github/open/<owner>/<repo>/<number>"` and `p.actions={click="open"}`. The dock worktree node uses `plotroom://github/worktree/<owner>/<repo>/<number>`. The SDK's built-in `open` pointer action handles the node's href in the clicking window, reaching `tern.route.link` without a host event. This is crucial: host `cx:open` broadcasts to every attached window and would create duplicate tabs. Do not substitute a focus gate, KV lock or canvas-only UI.

In `window.luau`, claim only these two route shapes. Validate owner/repository/positive integer components, require a source pane whose surface role is `plugin.plotroom.prs`, and check the requested identity is present in that pane's current surface (read only the relevant keyed node/dock subtree with `cx.session:surface`). Reject malformed/stale links with a toast and `{handled=true}`; unrelated schemes return nil. Never accept a cwd, command, executable or arbitrary external URL from a route. Repository mapping and launch cwd are obtained from plugin state/surface, not URL parameters.

Register palette commands `open-selected` and `worktree-selected`, available only for the focused Plotroom block, that read the stable selected dock node with `cx.session:surface` and invoke the same validated window action function directly. This gives keyboard-accessible PR actions without host broadcast or globally intercepting shell Enter. Host arrow-key selection and filter editing stay in the host; no host-side Enter shortcut should call `cx:open`.

For Browser action call `cx.browser:call({op="open",owner=sourcePane,url=canonicalPrUrl})`. Its awaitable callback receives a fresh window `cx`; check both awaitable errors and `result.error`, then dock the created block with `cx.layout:dock(browserPane,sourcePane,"right",{focus=true})`. The CLI help verifies the open operation and owner/url fields; **the exact created-block field under `result.ok` is unverified—confirm first from the installed runtime response during the initial smoke**, then use that one shape (not a heuristic list of guessed fields). If dock fails, report it and retain the already-open Browser PiP rather than launching an external browser or duplicating the page. Repeated clicks may open new Browser blocks; browser-reuse machinery is not needed.

### 5. Create safe PR worktrees and open tabs rooted there
Expose `worktree.open(launchCwd: string?, mappedPath: string?, repo: string, number: number, done: (path: string?, problem: string?, cx: WindowCx?) -> ()): ()`. Every process callback passes its fresh window context onward; never retain a window `cx`. Coalesce repeated in-flight requests for the same repository/PR in one window and show a starting/success/error toast. No process executes via shell interpolation.

Repository resolution:
1. Try the captured launch cwd, using `git -C <cwd> rev-parse --show-toplevel` and `git -C <root> rev-parse --path-format=absolute --git-common-dir`. Enumerate remotes and their fetch URLs; normalize HTTPS, `ssh://git@github.com/...`, and `git@github.com:owner/repo.git` to repository identity. Match **the PR base repository**, not its fork's head repository. Prefer matching `origin`, then `upstream`, then lexical remote name; never assume origin is the target or switch the source checkout.
2. If it does not match, try the saved `repos["github.com/"..repo]` path and revalidate it identically. A cwd subdirectory or existing linked worktree is valid.
3. Without a match, send `cx.session:event(sourcePane,{ev="action",act="choose-repo",value=repo})`. The host shows a labelled local-path input, validates the entered Git root/remotes before storing it, then says “Repository saved; choose Worktree again”. Expand only leading `~/` using HOME; otherwise require an absolute directory. Do not clone automatically, guess a repo from the title, or fetch into an unrelated checkout. Non-repository/bare-only paths get an actionable error.

Before mutations call `gh api --hostname github.com repos/<owner>/<repo>/pulls/<number>`, verify base identity and read `head.sha`/`head.ref`. Deleted fork repositories are permitted if GitHub still exposes the PR head ref. Get `git worktree list --porcelain -z`, preserving spaces/newlines in paths. The first main worktree establishes `<mainRoot>` even when launched from a linked worktree. Use:
- local branch `plotroom/<owner>/<repo>/pr-<number>`;
- fetched reference `refs/plotroom/<owner>/<repo>/pr-<number>`;
- directory `<parent(mainRoot)>/<basename(mainRoot)>.plotroom/<owner>/<repo>/pr-<number>`.

The worktree is a writable local branch at the PR's head, not a detached checkout. Keep the GitHub head branch name in the success message; do not change tracking or push policy automatically.

First inspect worktree/branch/path conflicts. If the expected branch is already checked out in a live worktree of the same common Git directory, reuse that path, including local edits/commits; never reset or pull it. If the deterministic target directory exists without that verified association, stop with a collision error. If the local branch exists but is not checked out, reuse it only when its tip equals the fetched PR head; otherwise report the branch conflict rather than overwriting it. Locked/prunable/missing records matching the target path or expected branch are errors requiring manual repair, not permission to prune; unrelated stale worktree records do not block this operation.

Run every Git inspection/fetch/worktree command through `process.luau` with bare `"git"`, exactly like gh; there is no second candidate list. Reuse one `resolveRepository(path, repo, done)` function in `worktree.luau` from both the host's mapping form and the window's worktree flow; callbacks accept optional fresh window `cx`, which is nil in the host. Enumerate with `git remote`, then `git remote get-url --all <name>`; validate each normalized owner/repository as nonempty non-dot path segments without separators/control characters before constructing refs/paths. Reject remote names beginning with `-` instead of passing them as fetch options.

For a new worktree, sequentially execute (each option/value a separate argv entry):

```text
git -C <root> fetch --no-tags --no-write-fetch-head <matched-remote> +refs/pull/<number>/head:refs/plotroom/<owner>/<repo>/pr-<number>
git -C <root> rev-parse refs/plotroom/<owner>/<repo>/pr-<number>
git -C <root> worktree add -b plotroom/<owner>/<repo>/pr-<number> <path> <verifiedHeadSha>
```

For a verified existing unused branch, omit `-b` and pass that branch as the final argument. Create only the required parent directories with `tern.fs.mkdir`. Compare the fetched SHA to metadata; if it changed concurrently, refetch metadata once and accept only an exact match, otherwise report that the PR changed and request Retry. Git's ref/worktree locks arbitrate cross-window races; if add reports a collision, reread the worktree list once and accept only a fully matching existing branch/common-dir/path. No `reset`, `clean`, force-checkout, `worktree remove`, auto-stash, pruning or branch deletion. A failure after partial creation leaves the path intact and reports it; a later retry performs the same reconciliation.

Use the verified literal SHA for new-branch creation, not the mutable fetched ref, so another window's fetch cannot change the checkout between verification and add. After a newly created worktree is added, verify its `HEAD` equals that SHA before reporting success; an already existing reused worktree intentionally keeps its own commits.

Use a 120-second timeout for fetch/worktree creation and 10 seconds for local inspection, plus `GIT_TERMINAL_PROMPT=0`. Reuse configured Git credentials/SSH for the matched remote; never rewrite remotes or credential settings. An authentication failure is shown with the exact failed operation, not repaired by token extraction.

After success, verify `git -C <path> rev-parse --show-toplevel` and that it belongs to the expected common Git directory. In the completion callback, return to the source pane's still-existing session, then call `cx.layout:new_tab({cwd=path})` (no command means the normal shell), and `cx.layout:name_tab(cx.session:tab_of(newPane),"PR #<number> · <repo>")`. If the source pane/session closed, report the completed path without opening in an unrelated current session. New tabs may repeat on separate user clicks; worktree creation must not repeat. Never run agent prompts, builds, repository scripts, or checkout operations in the source pane.

## Assumptions & contingencies
- The initial target is **local desktop Tern + github.com**, matching the verified environment. Browsing does not require a local clone. Do not execute local Git against a remote Tern pane path: detect a nonlocal source host and show “Open Plotroom on the local host to create a worktree” rather than silently using a same-named local path. Remote execution/Enterprise hosts are not implicitly promised by using the SDK.
- Saved filters use GitHub's search syntax; active queues refresh every 60 seconds, not instant webhooks. A search exceeding GitHub's cap is visibly partial; the user must narrow it for a complete queue.
- Worktrees default to the sibling `<mainRoot>.plotroom` hierarchy and reusable `plotroom/<owner>/<repo>/pr-N` local branches. No clone service, branch reset, auto-update of existing worktrees, or cleanup policy is introduced.
- Public docs and SDK main differ on input `features`; follow the explicit generated-declaration rule in step 3. The Browser API's exact success payload must be observed before hard-coding it. If the installed runtime lacks a required Browser/layout API, keep that acceptance criterion blocked and report the missing API/build requirement; never substitute an external browser or claim success.
- Running gh with its existing account is intentional; accounts can be switched by the operator outside Plotroom. Authentication is owned entirely by gh.
