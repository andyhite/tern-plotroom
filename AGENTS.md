# Repository Guidelines

## Project Overview

Tern Plotroom is a [Tern](https://tern.sh) terminal plugin, written in Luau, that renders one block, shown as Plotroom, for a live queue of GitHub pull requests, GitHub issues and Jira issues: one sidebar of typed saved views, keyboard triage, Browser docking, and one-key worktrees. The block's identity stays `plugin.plotroom.prs` (manifest block id `prs`) so existing PR panes restore. Data comes from the `gh` CLI (GraphQL), Atlassian's `acli` (Jira) and `git`; there is no server component.

There is one block and one palette command, `Plotroom: Open` (id `open`). The old `plugin.plotroom.issues` block and its `open-issues` command are removed; Tern has no pane migration hook, so an old Issues pane must be reopened through Plotroom (saved views and prompts are not touched, and nothing is migrated). The `KINDS` table (`prs`, `issues`) in `host.luau` replaces the old block-wide `Kind`: each kind fixes its label, icon (`merge`, `list-checks`; a name outside Tern's icon set draws blank), kv keys, allowed integrations, seed views, `?` list and prompt variables, and each saved `View` (`{id, kind, name, integration, query, logins, group, prompts}`) carries its own `kind`, so the details, actions and wording follow the active view (`State.kind` is only the active view's). In memory a view's id is `prs:<kv id>` or `issues:<kv id>` (the pinned PR's is `pin`); the stores stay kv `views-prs`/`views-issues` and `prompts-prs`/`prompts-issues`. `orderedViews` lists views in the sidebar grouped by integration and login, GitHub pull request and issue views together, Jira views alongside. Settings › Views lists a group per signed-in gh login (`ghActive.accounts`; the page reads them even with no GitHub view) and Jira's while acli is installed (`installed.jira`, probed when no Jira view shows it) or a Jira view exists, plus any other group a saved view sits under (a signed-out login, several logins). An account's or Jira's group ends in an Add view button (`vadd:github:<login>`, `vadd:jira:`): a view of that integration and explicit login, of `State.kind` where the integration allows it, else an issue view. A view's integration and logins never change in Settings (no Integration or logins row). Its Type row (`vkind`, GitHub views only) writes the view into the other kind's store under a new id (destination first, so a failure leaves the original), keeping name, query, logins and group-by while it still holds, and resets the prompts offered. Settings › Prompts lists both kinds' prompts. `jira.luau` reads Jira through `acli` (kv `jira-repos` maps a project to its repositories); `tracker.luau` holds the tracker-neutral `Issue` type and the name formats (`render`, `formatProblem`, `{github.user}`-style dotted vars); links are `plotroom://issue/...`, rpc op `issue`. Name formats (host table `formats`): new issue branches (kv `branch-format`, per-repo override kv `branch-formats`) and worktree folder names (kv `pr-dir-format`, `issue-dir-format`). An issue worktree is on its one live linked PR's branch (`github.linkedPrs`; several → the window's `choosePr` picker), else a new branch from a base the window's `chooseBase` picker asks for (`worktree.openIssue` answers `UNDECIDED` / `NEED_BASE`). PR worktrees are on the PR's head branch (`worktree.prBranch`; forks `<owner>/<branch>`). Item picker ids are `n<number>` (PRs) or `n<ref>` (issues); the action bar is `itemActions`; CSS selectors cover both surfaces.

## Architecture & Data Flow

Two Luau runtimes talk through Tern:

- **Host** (`plugin/host.luau`): runs where the block runs (the remote host's daemon for a remote pane). Owns per-pane `State` (module table `running`, keyed by pane), polls GitHub and Jira, persists prefs in `tern.kv`, returns a declarative `ui.el`/`ui.node` tree from `view`, and does all checkout work (git, gh, omp) and saved-prompt reads for the window. Registered via `tern.block.define("prs", {init, title, view, key, event, save})`.
- **Window** (`plugin/window.luau`): runs on the machine showing the window, so it never touches a checkout. Registers `tern.route.link` for `plotroom://github/<open|worktree|goto|agent|show>/<owner>/<repo>/<n>` and `plotroom://github/run/<owner>/<repo>/<n>/<prompt id>` links (and the `plotroom://issue/...` ones for issues), `plotroom://repos` and `plotroom://jira-projects` (the pickers behind Settings' Add repository and Add Jira project rows, sent back as the block's `add-repo`/`add-jira` actions), `plotroom://confirm` (the palette before a Settings Delete or Remove: it reads the block's hidden `main.confirm` JSON `{row, head, label, detail}`, lists Cancel first, and sends `confirm-delete`/`cancel-delete` with the row, which the host acts on only for the row it asked about), `tern.command` ids (`open`, `open-selected`, `worktree-selected`, `goto-selected`, `agent-selected`), reads host nodes by dotted key (the hidden `layer.queue.buttons.<open|worktree|goto|agent|prompt-<id>>` links that mirror the picker's action bar, the check rows `layer.queue.<required|runs>.run<i>`, and the issue sidebar's linked PR rows under `layer.queue.linked`) via `cx.session:surface`, and only follows a link whose node shows that exact href. Asks the user (pickers, consent) and arranges tabs/agents. `show` (a linked PR row) sends `{ev="action", act="show-pr", value=<PR URL>}` to the block the link came from, never another or a new one; the host selects the PR in the active view when that lists pull requests and has it, else lists it alone in `State.pin` (the sidebar's first scope, a pull request view, so the active kind follows it; fetched by `github.pull`, saved as `pin`) and leaves the other views in the sidebar.
- **Window → host requests** (host section "requests from window.luau", window `ask`/`answered`): window sends `{ev="action", act="rpc", value=JSON{id, op, ...}}` with ops `menu` (saved prompts offered under the active view, each with `worktree`: where it runs, and `split` when its agent opens beside the queue rather than in a tab), `worktree`/`issue` (with `users` when the prompt names `{github.user}`/`{jira.user}`; `worktree` false answers the main checkout, no worktree; `issue` also `pr`/`fresh`/`base` once picked), `where` (an item's noted worktree folder, for Go to tab), `checkout` (verify or clone a repository's checkout), `map-jira` and `jira-projects` (a Jira project's repositories), `repos` (saved repositories and signed-in gh logins) and `profile` (one login's repositories); the host answers in hidden node `main.r<id>` (JSON), renders, then opens `plotroom://rpc/<id>`, which only the asking window acts on. Hidden `main.rpc` holds the protocol version (`RPC_PROTOCOL` in host, `PROTOCOL` in window, now 13); bump both together when the request/answer shapes change, since a remote host may run another Plotroom version.
- **Repositories and checkouts**: views span repositories, so the block has no repository of its own. `init` resolves the launch directory (`launchCwd`) and saves its main checkout under kv `checkouts` (lowercase `owner/name` → path; `""` = listed without a checkout, as Settings › Repositories › Add repository does). Without a checkout, a Worktree, agent or prompt on that repository asks for one through the window's `checkout` op (`claim` verifies a folder or runs `gh repo clone`); per-repository setup commands are kv `setup-commands`, branch formats `branch-formats`, the worktree folder `worktree-root`.
- **Worktree card** (`State.notes`, by item key; the card and the rows' Worktree badge): memory only, but a cache of git, never the source, so a fresh block or one after a plugin reload shows the worktrees that exist. `scanWorktrees` (nested in `blockDef`, asked by every `view`, idempotent) runs `worktree.scan` for each saved checkout of the repositories in the shown snapshot (a Jira issue's: the project's mapped repositories) when that snapshot was not scanned yet (each refresh result, a view switch), after a Worktree attempt (`noteWorktree`), a removal or a saved checkout (`state.scanned = nil`): one `git worktree list` per checkout plus, with a PR's worktree there, one `git config` read; no per-row spawns. `applyScans` reconciles: a listed worktree of a listed item with no ok note gets one, an ok note whose worktree its scanned checkout no longer lists goes, and a failed scan, or one that a note change overtook (`noteSeq`), changes nothing. `inspectSelected` reads `git status` for the selected item only (debounced, once per refresh); `dirty` is nil until then. `NOTE_CAP` bounds only the attempts git has not confirmed.
- **Shared helpers** (no cycles): `host → github, input, jira, keys, process, tracker, worktree`; `window → worktree`; `worktree → process, github, tracker`; `jira → process, tracker, github`; `github → process, input, tracker`; `tracker → input`; `process`, `input`, `keys` have no requires.
  - `github.luau`: `gh` runner, paged GraphQL `search`, `parsePage`/`normalize`/`classify`, account switching, rate-limit quota, the repository picker's cached `accounts`/`repos` lists.
  - `worktree.luau`: repo resolution (`currentRepository` also finds the main checkout), worktree create/reuse (`M.open`, `M.openIssue` from the saved checkout, folder named by the caller's format), `M.remoteBranches`, removal (`M.remove`, host only, never forced: the worktree card's Remove worktree), `within` (path inside a worktree), `M.scan` (what the card is read from: a checkout's worktrees by item key, each item known by its branches or folder names, `Want`, which host `formats.want` builds from the current formats; read-only) and `M.dirty` (`git status` of one worktree), ref validation.
  - `process.luau`: the single process runner `M.run(argv, opts, done)`; recovers PATH via login shell, always calls `done`, never throws.
  - `input.luau`: pure text model, single-line or `multi` (UTF-16 offsets for the SDK).
  - `keys.luau`: the queue's one-key shortcuts (action ids and defaults) and kv `keys` (action id → key, `""` removed; per machine, shared by pull request and issue views): `load` the effective map and why it could not be read, `save` (fail-closed), `action`/`problem`/`shape` for dispatch and validation. The key handler, `?` lists, keycaps and Settings › Keys all read it, so nothing else hard-codes a queue key.
- Persistence: `tern.kv` keys `views-prs`, `views-issues` (saved views per kind, `{version, nextId, items}`), `prompts-prs`, `prompts-issues`, `checkouts`, `setup-commands`, `worktree-root`, `jira-repos`, `keys`, `branch-format`, `branch-formats`, `pr-dir-format`, `issue-dir-format` (host, per machine), `agent-recent` (window). Issue lists sort by status category (`tracker.byStatus`: In Progress, To Do, Done); Jira search adds `ORDER BY priority DESC, updated DESC` for order within a category. Store changes fan out to other live blocks via `propagate`. host.luau is at Luau's 200-top-level-local limit: group new helpers into an existing table (`formats`, `me`) instead of adding locals.
- Block `save` is version 2 (any other version restores fresh): `launchCwd`, `activeViewId` (the view's id in its own kv store; `pin` for the pinned PR), `activeKind` (`issues`; absent means `prs`, which is also what a save from the older PR block reads as), `activeLogin`, `pause`, `pin` (the pinned PR's URL).
- Settings multi-line text: Tern 0.8.3 `prefs` has no multi-line control, so a prompt's text is an `editor` node inside a `col` child with `role = "omp.prefs.editor"`, which `prefs` draws as a card over the page; keys still reach the block's `key` handler.
- Settings pages (`PAGE_DEFS`, Tab order): Views, Prompts, Keys, Worktrees (folder and name formats), Repositories (checkout, own branch format, setup commands), Jira projects, Refresh (id `connection`); Settings reopens on the page last shown (`State.settingsPage`). `pageContent` builds cards with its local `section`/`row`: Views a card per group (`group:<lowercased label>`), Prompts a card per kind; an open view's or prompt's form is its own card `form:<id>` (first in its group or kind, it takes over that card and its title) whose first row is its summary row (`vopen:`/`popen:`, Edit turned Done). An open view's Delete row (`delete:`) comes right after its summary row, and plotroom.css lifts its button onto the summary row, left of Done; its label is hidden, so a failed delete warns on the summary row. Pages have no lead and rows carry their meaning in the label: a `hint` only shows data (a collapsed view's kind and query, a prompt's first line, a name format's variables, the refresh pace) or what a captured shortcut row takes. An Add button is a section of its own whose id starts `add` holding one action row with an empty label, which plotroom.css draws as a bare button: `add:<…>` under its list, `add-to:<…>` titled with an empty group's label (prefs skips a section without rows). Delete and Remove rows set `Settings.confirm` and open `plotroom://confirm` (window.luau's palette); there is no Settings overlay. Controls: `choice` for one-of rows (`style = "segmented"`: Enter switches to the next option, as segments draw no keyboard highlight; `style = "menu"`: Enter opens `pick`, arrows move, Enter picks; hover sends `select` `"<row>=<value>"`), `multi` chips; `setValue` takes every `change` (string for a choice, array for chips). Text rows: `props.editing` shows the text edit over any `pick`, so a click on another row or button (the prefs event handler) first ends the single-line edit: it saves, a refused draft keeps the row open with its warning, an empty one is dropped; a click inside the edited field keeps the draft. Shortcut rows (`key:`, `pkey:`) capture the next key: no typing, Backspace removes, Esc keeps (a click elsewhere keeps too).

## Key Directories

- `plugin/` — the plugin (`plugin.toml` manifest, `*.luau` modules, `plotroom.css`). Everything shipped lives here.
- `plugin/tests/` — `regression.luau` (fake-SDK suite + bench), `check.luau` (pure assert selftest, also runnable in-app), `runtime.luau` (smoke driver against real Tern/git).
- `scripts/` — `check.py` (the verification gate) and `tern-0.8.3.d.luau` (pinned SDK type snapshot, sha256-checked).
- `.github/workflows/check.yml` — CI; `.omp/plans/` — historical design plans (README supersedes them).

## Development Commands

```sh
tern plugin link ./plugin          # install for local use
python3 scripts/check.py tools     # download pinned luau 0.742 + luau-lsp 1.70.1 (macOS / Linux x86_64)
python3 scripts/check.py           # all: test + types + bench + smoke
python3 scripts/check.py test      # regression suite only (also: types | bench | smoke)
python3 scripts/check.py --ci      # what CI runs: smoke reported NOT RUN
tern plugin types plugin           # refresh gitignored plugin/tern.d.luau for editor types
```

Tool lookup order: env `LUAU`/`LUAU_LSP`/`TERN` → `~/.cache/plotroom-check/` (`$XDG_CACHE_HOME`) → PATH. Missing tool = failure, not skip. `PLOTROOM_BENCH_BUDGET_MS` (default 250) caps the slowest bench row. `types` fails on **any** luau-lsp diagnostic, warnings included, over `plugin/*.luau` and `plugin/tests/*.luau`.

## Code Conventions & Common Patterns

- `--!strict` at the top of every module. Modules are `local M = {}` + `function M.x`; `host`/`window` expose only registrations.
- Naming: files lowercase single word; functions/locals camelCase (`loadStore`, `kvSet`); constants SCREAMING_SNAKE (`POLL_MS`, `GH_TIMEOUT_MS`); types PascalCase, `export type` when shared; action/check ids kebab-case (`retry-checks`, `prompt-<id>`); kv keys lowercase words.
- Async is callbacks only, no coroutines. Shape: `done(value?, problem?, cx?)`. `process.run` is the only way to spawn anything.
- Errors are values: `Problem = {kind, message}`, kinds `auth|missing|rate-limit|invalid|not-found|failed|account|superseded` (`github.luau` L10-12). Wrap `tern.kv`/`tern.json` calls in `pcall`; never overwrite unreadable or malformed storage; validate untrusted input at the boundary (`validStore`, `parsePage`, size caps).
- Stale-callback guards are mandatory: check `alive(state)` and `state.gen` in host callbacks; window uses `defer` to fetch a fresh `cx`.
- Security: every command is an argv array (`{"git", "worktree", "add", ...}`); never build shell strings.
- UI: native Tern kinds only (`picker`, `prefs`, `list`/`item`, `overlay`, `kv`, `badge`, `md`, `meter`, `spinner`, `icon`…); there is no native button, so buttons are the picker's action bar (`itemActions`) or `item` rows with `hint` keycaps and `actions={click=...}`. No `ui.el` with plugin classes. Keys must be stable because window locates nodes by dotted key. Items are keyed `n<number>`; picker `layer.queue`; Settings is `layer.settings`, a `prefs` in the layer (Tern's right-docked side sheet) drawn over the queue picker.
- CSS (`plotroom.css`): only where no kind or prop covers it (a handful of rules); never restyle what a kind draws. Every selector starts with `[data-surface='plugin.plotroom.prs']`; use Tern tokens; no logical properties, `rem`/`ch`, or `:has()`.
- Deliberate shortcuts carry a `ponytail:` comment naming the ceiling and upgrade path.
- Annotate with SDK types from `tern.d.luau` (`BlockCx`, `WindowCx`, `Node`, `BlockView`, `ProcessResult`, `TimerHandle`, ...).

## Important Files

- `plugin/plugin.toml` — manifest: id `plotroom`, `host`, `window`, `styles`, one block `prs` (title Plotroom, icon `merge`).
- `plugin/host.luau` (~5000 lines) — state type ~L64, storage ~L107-203, lifecycle `retire`/`alive`, window requests (`reply`, `menu`, `prepare`, `rpc`), views, block define, event handler. Its main chunk sits at Luau's 200-local limit with no headroom: a new top-level `local` fails to compile ("Out of local registers"), so put new helpers in a module or nest them inside `blockDef` or an existing function.
- `plugin/window.luau` — link routing, palette commands, requests to the host (`ask`, `answered`), worktree/agent flows (`finishWorktree`, `finishAgent`: `cx.agents:start`, as `omp --model <m>` when the prompt names a model, `worktreePr`, `pickAgent`). No consent step: agents start once the worktree is ready. `selftest`/`smoke` commands only when `PLOTROOM_SELFTEST=1`.
- `scripts/check.py` — pins at L51-56 (SDK sha256, Luau 0.742, luau-lsp 1.70.1, Tern 0.8.3); bundle builder `build_bundle`; stages `check_test`/`check_types`/`check_bench`/`check_smoke`.
- `scripts/tern-0.8.3.d.luau` — tracked SDK snapshot used by `types`; changing it requires updating the sha in `check.py`.

## Runtime/Tooling Preferences

- Luau (Tern's embedded runtime), not Lua 5.x: no `goto`, string/UTF-8 helpers per Luau. Type-checked with luau-lsp 1.70.1 against Tern 0.8.3 definitions.
- `scripts/check.py` is Python 3.9+, stdlib only; no pip, no package.json, no Makefile. Do not add dependencies.
- Smoke needs real `tern` 0.8.3, git ≥ 2.36 (`worktree list --porcelain -z`) and `omp` on PATH (worktrees are created with `omp worktree add`); it is local-only (CI skips it). CI: ubuntu-latest, `tools` then `--ci`, actions pinned by SHA.
- `plugin/tern.d.luau` is gitignored editor output; never commit it or depend on it in checks.

## Testing & QA

- No framework. `check.py test` bundles every `plugin/*.luau` and `plugin/tests/*.luau` into one temp script (each module wrapped as `function(tern, require, os)`) and runs `luau` on it. Pass = exit 0 and stdout `REGRESSION cases=N failed=0`.
- Add cases to `plugin/tests/regression.luau` with `case("module: behavior", fn)` (host context) or `windowCase(...)` (window context). Each case gets a fresh `World` (`newWorld`): fake SDK with virtual clock (`advance`/`runUntil`/`flush`), in-memory `fs`/`kv`, and `w.respond(fn)` to answer `process.run` spawns; unmatched spawns fail the case at `w.finish()`. Assertion helpers: `eq`, `same`, `yes`, `has`, `lacks`.

```lua
case("input: clean drops only malformed bytes and control characters", function(w: World)
	local input = w.load("input") :: Input
	eq(input.clean("é\x80b"), "éb", "stray continuation byte after a valid character")
end)
```

- Prefer behavioral assertions (rendered text, argv, kv contents, toasts). Case names are prefixed by module (`github.search:`, `worktree:`, `host:`).
- Pure helpers with no SDK dependency go in `plugin/tests/check.luau` (bare `assert`), which runs both in the bundle and in-app via the `selftest` palette command.
- No coverage tool or threshold. Bench rows (`BENCH <name> ms=…`, 1000 PRs) must stay under budget; smoke covers the real-git worktree scenarios listed in `scripts/check.py` (create, reuse, dirty reuse, advanced head, post-checkout hook, existing branch, deleted head branch, `.github`, recovery, fork PRs, folder names, issue worktree, Jira issue worktree, issue on a linked PR, remote branches, scan) plus a block on an attached loopback host making its worktree through the real window → host → window link flow.
- Fake-SDK window cases that need the host's answers use `linkQueue`/`agentScene`, which `w.link` a real host block to the window's pane.
- The fake gh/git models (`newGh`, `newGit`) answer what worktrees ask: `gh.meta` (PR heads, `headRepo` absent = a deleted fork), `gh.linked` (an issue's linked PRs), `git.served`/`git.defaultBranch` (the remote's branches), `git.config` (what `git config` wrote). `scene`/`openWt` (PR worktrees) and `issueRepo`/`openIssuePlan` (issue worktrees) build on them.
- The fake `tern.json.array` and decoded JSON arrays carry a protected metatable as in real Tern, so `table.clone` on them fails in tests too; copy with a loop. `cx:frame` ops are recorded in `w.frames` (`caretOf(w)` reads the last `focus` op).
- Before finishing any change: `python3 scripts/check.py` (or `--ci` without Tern) must pass clean.
