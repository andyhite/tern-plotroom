# Changelog

All notable changes to Plotroom are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The version in `plugin/plugin.toml` is the release; the protocol a window and its hosts speak is separate (see [docs/reference.md › Setup](docs/reference.md#setup), Remote hosts).

## [Unreleased]

### Added
- Preview checks by state: Failing, Running and Queued, each headed with its count, then Passed and Skipped in one fold that starts folded ("Passed 12 · Skipped 1"). Each check shows its CI (workflow, app or status host) and how long it ran or has been running ("45s", "6m 24s", "1h 05m"); required ones say Required. While a check is unfinished, the previewed pull request's checks are read again every 30 s, until the selection moves or nothing is pending. This replaces the Required and Optional groups.
- Plotroom's omp extension (`plugin/omp/plotroom.ts`): every agent Plotroom starts runs as `omp -e <plugin folder>/omp/plotroom.ts` (with its action's `--model`), a run id and Plotroom's data directory in its environment, and gets the tool `plotroom_propose_review`, which checks a proposed pull request review and writes it to `runs/<run id>/review.json` in Plotroom's data directory for the Draft review block. Agents now always start as omp, not Tern's agent command; when the extension is not in the plugin folder on the block's host, the agent starts as before and a toast says why.
- Draft review block: when an agent Plotroom started ends a turn with a new Draft review, a second block (Draft review) opens beside it with the review on the pull request's diff: the summary and verdict at the top, one card per comment grouped by file with the lines around it, and comments off the diff listed apart (they cannot be kept). `j`/`k`, Space (keep or drop), `e` (edit), `1`/`2`/`3` (verdict) and ⌘↵ (send) are shown beside their controls. **Send to agent** hands the agent your kept comments as edited, the dropped ids, the verdict, the summary and an optional line of instructions; nothing is posted by the block. A head that moved since the review is said, and a gone agent gets **Copy**. Hosts speak rpc protocol 46 (op `review`).
- Key footer: a line under the queue lists up to five keys that work for what is selected now, each with what it does: Commands (`.`) and Shortcut list first, then the Next move, then the most used. A key with nothing bound is not listed, and a saved action's key shows that action only where it beats the built-in key. The preview's Unsnooze button shows the Snooze until tomorrow key, which ends a snooze.
- Commands › Configuration › Copy usage report: plain text with how often each queue action, Commands row, Tern's palette command and action ran (on this machine and on the block's host) and how each agent run ended, with the median run time. Counts live in kv `usage`, the newest 1000 runs one file each (`runs/<run id>/run.json` in Plotroom's data directory) with kv `runs` as their index; a run log kept in kv `runs` by an earlier version is moved into files once. Nothing leaves the machine.
- Get started: a first-run checklist above the preview until every line is done or it is dismissed (Commands › Get started shows it again): `gh` installed and signed in, `omp` installed, a checkout for each listed repository without one, and the one-key shortcuts (Use them / No thanks). Each line not done has one action: a setup guide, **Use <folder>** for a checkout found, or a folder to choose (a new or empty one gets a clone).
- Checkout detection: a repository with no checkout is offered the folder Plotroom opened in, or the folder of an open Tern pane on the same host, when it is inside a checkout with a remote on that github.com repository (verified as Settings › Repositories verifies; the disk is never scanned). Worktree, an action and Type a prompt… offer it as **Use <folder>** before asking for a folder.
- Stage on every item: each row's first badge and the preview's first fact say Merged, Closed, Needs you, Agent working, Blocked, Ready to merge, PR open, Worktree or Not started, derived from GitHub, Jira, git and the item's agent on every render. It replaces the Merged and plain Closed badges, the Working and Needs input badges and an item's Worktree badge when they would say the same. The pull request search also reads GitHub's merge state.
- Suggested next move: the selected item's stage picks one move (Worktree, Review, Go to agent, Address feedback, Re-run failed checks, Merge…, Ready for review…, Draft PR…, Remove worktree…), shown as the first Commands row under **Next** and as a button below the preview's title. It runs exactly as its own command does. The new queue action **Next move** has no default key; the one-key set binds it to `x`.
- **Now**: the first entry in the sidebar and what a new block opens on. It ranks everything that needs you, each row saying why: agents that need input, your Blocked pull requests, reviews requested of you (oldest first), your pull requests Ready to merge, unread notifications you take part in, then New or Changed issues assigned to you on GitHub and in Jira. It reads fixed searches per signed-in `gh` login, Jira's open work assigned to you and your notifications, with every refresh of the queue, on any view. Snoozed items follow Show or hide snoozed. One count, `N need you`, shows in the status bar; clicking it shows Now (also **Plotroom: Show what needs you (Now)** in Tern's palette).
- Agent questions answered in Now: an agent that needs input shows its last message on its Now row and in the preview, with **Reply…** (asks for one line and sends it as Message agent… does) and **Go to agent** (Commands › Now). An agent that stopped waiting before the reply is sent gets Message agent's toast and nothing is sent; once it stops waiting, its row leaves Now.
- A view or Now as a Board: each view's **Layout** (Settings › Views: List or Board) is saved with the view, and Now's in Settings › Views › Now; **Show as Board** / **Show as List** (Commands, **Show Now as Board** / **Show Now as List** on Now) switch and save it. A Board lays the list out in columns by stage (Needs you, Agent working, Waiting, Ready to merge; Not started, Worktree and a view's Merged or closed in a fold), its cards in the list's order after its sort, search and snoozing; Up/Down move in a column and Left/Right across (the new queue actions **Move left (Board)** and **Move right (Board)**, `h`/`l` in the one-key set). The selected card is the selection, so Enter, the Next move, Commands and snooze act on it as on the List. A block narrower than 80 columns shows the List. A view saved before this has no layout and is a List.
- End-of-run report: every agent's prompt, an action's or a typed one, ends with a fixed contract asking the agent to end each turn with a `plotroom-report` JSON block (`attention` ok / stuck / needs-human, `reason`, `commit`, `pr`, `evidence`, `blocker`). Plotroom reads it from the agent's last message when the turn ends, keeps it on the run record and shows its attention, reason and blocker on the Agents row and preview; a missing or malformed one shows **No report**. Settings › Actions shows the contract read-only under the prompt editor. It is a claim, never an outcome.
- Checked outcomes: each action names an **Outcome** (Settings › Actions: None, Review posted, PR opened, Pushed, Replied to feedback, Merged; the defaults name theirs, Plan none). When an agent's turn ends Plotroom checks it on GitHub as the run's login and records **Verified** or **Not verified** on the run; a fact it cannot read is **Unchecked** and checked again at the next refresh, and a Merged run is checked until it merges or its agent exits. The verdict shows on the row, the preview, the Agents list and Now. An idle agent whose outcome is Not verified, or whose report says stuck or needs human, is Needs you and ranks first in Now (Go to agent, no Reply…). The usage report counts each action's outcomes. Hosts announce protocol 36 (the `outcome` request).
- Checkers: an action's **Checked by** (Settings › Actions; none by default) names another action that a fresh agent runs on the same item, never in the builder's pane, when a run's end-of-run report names a new commit. The new default issue action **Check** verifies the work in the worktree against the acceptance criteria, posts nothing, and reports `check` pass or fail with `findings`; it checks Implement and Fix. Acceptance criteria are saved on the run at dispatch (a GitHub issue's task-list lines, a Jira description's Acceptance criteria section, else the description, capped) and the builder and its checker get the same `{criteria}` block. A pass marks the run **Checked**; a fail shows its findings in the preview and Now, with the item at Needs you; a check with no verdict fails. Settings refuses an action that checks itself. Hosts announce protocol 37 (the `criteria` request and the actions' `checker` field).
- Checker agreement: **Disagree with check…** (Commands › Actions, while the item's newest agent is a checker with a verdict, even once it exited) records your disagreement, with an optional one-line reason, on the checked run in the run log. A checked run counts as agreed once its work merges (asked of GitHub every ten minutes as the run's login) or seven days after the verdict, unless you disagreed. Copy usage report adds **Checker agreement**: checked runs, disagreements, undecided runs and agreement over the last 20 decided runs beside the Autopilot gate (80% over 20).
- Chains advance only on a Verified run or a passing check: a Next action starts once its run's outcome is Verified, or, for a checked action, once its check passes; a Not verified run stops the chain with a toast and the item at Needs you, and an action with a Next action but no outcome or checker starts nothing, saying why. A failed check starts the action again as a fix round, with the checker's findings as `{findings}` and the same acceptance criteria; a run with no new commit is not checked again and starts another round. A chain stops at Needs you after 3 failed checks, 3 runs without progress or 3 failed starts (each retried after 30 s), with the limit as the item's badge in Now; the counters live on the item's runs in the run log and begin again when an action is started by hand. A due step survives a plugin reload and never starts twice. Hosts announce protocol 38 (agent-status's `stop`).
- Settings › General › **Reset all settings**: after a confirm (Cancel first), clears every saved setting (views, actions, keyboard shortcuts, repositories, checkouts, branch formats, setup commands, Jira projects' repositories, name formats, Now's switches, Summary settings, Get started, ignored checks) so the defaults come back in every open block, malformed stores included; triage, usage, runs, agent links and Summaries stay.
- Settings › Views › **Now**: switch each of Now's reasons (Blocked, Review requested, Ready to merge, Notifications, Assigned), each signed-in `gh` login and Jira on or off, and **Include team review requests** (off by default; a request asked only of a team names it in the preview). What is off is not read at all, so it costs no GitHub quota, and leaves Now, its heading, the pane title and `N need you` at once in every open block. With every reason off Now lists only agents that need you. The switches live in kv `now`; one that cannot be read is never written over.
- Ignored checks: **Ignore this check…** (Commands › GitHub - PR, on a pull request with a failing check not yet ignored) picks one of its failing checks by name and, after a confirm (Cancel first), ignores that check in the PR's repository. A pull request whose only failing checks are ignored ones is not Blocked and is not in Now for them; the check still shows failing in the preview, marked **Ignored**, and still keeps the PR out of Ready to merge. Settings › Repositories › **Ignored checks** lists them, each with Remove. They live in kv `ignored-checks`; a store that cannot be read or is malformed ignores nothing and is never written over. Hosts announce protocol 44 (act's `check`).
- **Likely flaky**: a Blocked pull request's failing check is marked Likely flaky when no failure annotation blames a file the PR changed and it failed at least 3 of the base branch's last 20 runs of its workflow, or an earlier attempt passed on the same head commit. The preview's checks show the mark and why; a row whose every failing check is marked says **Checks failing (likely flaky)** (never when the PR has more checks than are loaded). Plotroom judges at most 10 pull requests a refresh, once per head commit, and keeps each workflow's base history an hour. Actions get `{flaky}`, and the default Watch re-runs a marked check without re-checking the base branch.
- Settings › Actions › **Model** is picked from omp's list instead of typed: omp's default, the role aliases (omp's `@plan`, `@slow`, `@smol` and your config's, each with the model it names), then `omp models`' chat models grouped by provider, filtered as you type. A saved model omp no longer lists stays selected, marked **Not in omp's list**. When omp cannot list models the row stays a text field with its value kept. A new **Effort** per action (omp's default, Off, Minimal, Low, Medium, High, XHigh, Max, Auto) starts its agent with `omp --thinking <level>`. Hosts announce protocol 42 (the `models` request and the actions' `effort` field).
- Merging the base before conflicts: an action that resolves conflicts (the default Watch) on a pull request GitHub reports conflicting first has Plotroom merge the base into its clean worktree, take conflicted lockfiles it knows from the base and regenerate them (npm, pnpm, Cargo, Go, Poetry, uv, Bundler, Composer), and commit the merge when nothing else conflicts; nothing is pushed. The agent's prompt ends with a `<merge>` block listing what was done and the files still conflicted. Hosts announce protocol 41 (the worktree request's `premerge`).
- Commands › GitHub - PR › **Push empty commit…**: for an open pull request whose own branch is up to date with its base and free of conflicts (never a fork's branch), a confirmed plan (Cancel first, naming the account, branch and head SHA) gives the branch a new head so its checks run again, through GitHub's git database API with no checkout: a commit with the head's tree and the head as parent, then the branch moved to it without force. A branch that moved since the plan gets nothing pushed and "The branch moved; refresh and try again."
- Review recency: someone else's open pull request you approved says **New commits since you approved** in its row's detail once its head is no longer the commit you approved (it is Changed too). A pull request whose review of yours was dismissed is Review requested in Now (one more search per login, of open pull requests you reviewed) and its Next move is Review. Both are read from GitHub on every refresh (your latest review and its commit); nothing is stored.
- **Summary** at the top of a pull request's or issue's preview: once the cursor rests on it for about a second and its details load, one `omp -p` call with no tools (the model from Settings › General › Summary model, default `@smol`, picked in the same picker as an action's Model) writes 2 to 4 plain sentences from its title, author, description, changed files and newest comments, shown as plain text with **Summarizing…** meanwhile. Cached per machine in kv `summaries` (the newest 200) by the item and its head commit or update time; Settings › General › Summary turns them off. The detail load now also reads a pull request's first 30 changed files and the 5 newest comments of a pull request or issue. Hosts announce protocol 45 (the `models` request for `summary:model`).
- **Next in Now**: a new queue action (no default key; the one-key set binds `n`; also Commands › Now) shows Now and selects its most urgent item, then each next one in Now's ranking. Now's heading reads `N left` at rest and `n of N` while walking; a hand move or a change of the list stops the walk, and the next press resumes from the selected item.
- A working agent shows how long it has worked (`m:ss`) on its Agents row, its item's Now row and the previews, and, once its action has 5 finished runs in the run log, a thin bar estimated from their median duration (it eases toward 90% at the median and is never full before the run ends). The view is drawn again once a second while a clock shows. Hosts announce protocol 39 (agent-status's optional `since` and `expected`).
- Failing checks' logs: for each failing GitHub Actions check (at most 5), Plotroom reads `gh run view <run> --log-failed --job <job>` once per check and head commit, keeps 12 lines before and 3 after each error line (else the last 30), at most 120 lines per job, gaps marked `… N lines`, CI markers stripped, and finds up to 5 `path:line` mentions of the pull request's changed files. The preview's Checks section shows each failing check's first error line, with its excerpt in a fold. The new pull request prompt variable `{failures}` holds each failing check's name, link, changed-file lines and excerpt, at most 8000 bytes; the default Watch uses it. Hosts announce protocol 40 (the worktree request's optional `failures` field).
- Arrival ring: when a refresh moves an item into Needs you or Blocked from another stage, its queue row is ringed in that stage's colour (accent, red) for about 1.4 s, then fades; a move into Ready to merge rings green, and an agent that starts needing you rings its row too. One error toast per refresh names the item and why (`o/r#12: Fix checks · 2/5 failing`, or counts several); a pull request Blocked only by conflicts does not toast. Not for a change you made with an item command in that block; under reduced motion the row is tinted instead. New and Changed are unchanged.
- Tern-level keys: ⌃⌥⇧Q **Go to Plotroom** focuses this session's Plotroom block, or opens one when there is none; ⌃⌥⇧I shows what needs you (Now); ⌃⌥⇧A goes to the first agent that needs input. Tern's default keymap binds none of them; `keybinds` in `settings.json` can replace or unbind them.

### Changed
- Tern's palette lists Plotroom's commands under one **Plotroom** heading with no `Plotroom:` prefix (rows read **Open**, not "Tern Plotroom › Plotroom: Open"). Palette search matches titles only, so "Plotroom" no longer finds them; the usage report names them by the same titles.
- Minimum Tern is now 0.9.13 (was 0.9.8): Plotroom type-checks against Tern 0.9.13's SDK, and smoke refuses an older Tern.
- End-of-run report: agents end every turn by calling the `plotroom_report` tool of Plotroom's omp extension instead of writing a fenced `plotroom-report` block. The tool checks the report and refuses a malformed one with the reason, so the agent fixes it and calls again; Plotroom reads the turn's last accepted call from the agent's transcript, reading it again each second for up to 10 seconds while Tern has reported the turn's end before the transcript shows it; closing the agent's block during that wait still records the turn, with what was last read. A message sent to the agent during that wait no longer gets the new turn's report recorded for the turn that ended. A fenced block in the agent's message is no longer read, and an agent started without the extension records **No report**.
- Draft review is now a focused workspace: a clickable findings navigator, one readable diff and Markdown feedback pane, verdict and Send controls at the top, and explicit Edit/Done controls. Narrow panes stack the navigator above the content. The review uses Tern's UI font for prose, monospace for code, neutral button rings and native selection; loading and sending protect edits from being lost or changed mid-handoff.
- The default Review and Quick review end in a Draft review instead of asking: the agent proposes its findings with `plotroom_propose_review` and ends its turn, then posts exactly what you send back from the Draft review block as one review, or revises when your instructions ask for changes. A pull request head that moved since the review is said and proposed again, never posted. Without the extension the agent says so and asks as before. Review posted is still their outcome, Verified once the review is posted. Saved actions keep their own text (delete one and Add missing defaults to get the new default).
- One meaning per colour (DESIGN.md › The Color Meaning Rule): accent is your turn, red needs fixing, green is done, purple is an agent working, amber is checks running; everything else is neutral. Needs you, Needs input, Not verified, Check failed and Changed turn accent; Agent working and Working turn purple; Merged and Completed turn green; Checks failing turns red. Open, Closed, Review required, Behind base, Jira's in-progress statuses, worktree states (Clean, Uncommitted changes, Not at PR head, unpushed), the Jira tag, item numbers, diff sizes, stale or partial notes, the Remove, Delete, Next and Save buttons and links are neutral.
- The Next move of a Blocked pull request with failing checks is **Re-run failed checks** only when every failing check is Likely flaky; otherwise your own PR's is the **Watch** action, and someone else's has none.
- A Blocked pull request shows one chip per reason, most severe first, each naming the job that clears it: **Address changes**, **Reply · N unresolved**, **Fix checks · N/T failing** (or **Re-run · likely flaky** when every failing check is Likely flaky), **Resolve conflicts**. The row's detail says the first one's who or what ("@maria-k asked 4h ago", "Conflicts with main") in plain text, the preview lists every reason under Blocked by and the unresolved review threads (author, file:line, first line, a link to the thread), and Now's Blocked rows and Board cards show the chips. Unresolved review threads now block a pull request that is not approved, and your own goes to **Address feedback**. The pull request search also reads each PR's unresolved threads and latest reviews.
- Protocol 39: a pull request's worktree answer carries `{flaky}`. A window still asks older hosts; their actions read `{flaky}` as none.
- The default Address feedback, Implement, Fix and Plan ask for approval with choices and a default instead of a typed format, and draft what they would post only once you pick it. Address feedback asks which items by category (all by default) and whether to post replies, then shows full replies for just the picked items before pushing. Implement and Fix no longer draft a ticket comment in their report; they ask which of Mark PR ready, Comment on the ticket and Move to <status> (when one fits) to do, none by default, and show a picked comment before posting it. Plan asks to file all tickets (the default) or only the first slice. Saved actions keep their own text.
- The default Review and Quick review group findings by severity (P0 · blocking … P3), ask a Question only when its answer would change a severity, a blocker or the recommendation, and no longer draft a review body in the report. Their approval is one ask with three choices: which comment groups to post (blocking ones by default), the review action (the recommendation by default; only Comment or None on your own PR) and the body (None by default, or a draft from your picks shown before posting). With no body, Request changes and Comment get only the posted items' headers. Saved actions keep their own text.
- Now is more accurate. It reads every signed-in `gh` login's notifications as that login (a login that cannot read them says so alone; Mark all notifications read… names each account and marks each login's threads as that login), says when a login's notifications fill the one page it reads (`showing the newest 50; the rest are on github.com`), leaves out an assigned issue whose changes since you last saw it are all your own (assigning it to yourself, edits, comments; someone else's change lists it again), reads Jira's assigned work from the open sprint as **My sprint** does while the site has sprints, and its heading reads `N assigned: new or changed`.
- Worktrees lists only linked worktrees, one group per repository: a repository's checkout itself is no longer listed, and the **Main** badge and preview fact are gone.
- Each Worktrees row is titled by its branch (a detached worktree reads "(detached)") instead of the worktree folder's name; the worktree's full path is the line under it.
- The pane title and Now's heading say what needs you by reason (`2 agents need you · 1 Blocked · 3 reviews requested`) instead of a bare `N need you`; the status bar's `N need you` stays the one cross-pane count and the one that is a button. The pane title no longer counts the view's items (`My PRs (12)`), and the queue's heading no longer shows Tern's result count at its right: both repeated the sidebar.
- Protocol 35: Mark all notifications read… is planned as `mark-read` (was `inbox-read`), so a window asks only hosts that run this release.
- Protocol 34: a repository's missing-checkout answer may name the folder found for it. A window still asks protocol 33 hosts, which ask for a folder as before.
- Protocol 33: a window asks only hosts that run this release (removed rpc ops raise the minimum).
- Default actions set every relevant option: Review, Quick review and Check run on `@slow`, Plan on `@plan`; Quick review opens beside the queue; Implement and Fix lead into Watch as their Next action. Saved actions are not changed: a fresh profile gets the new defaults, and Settings › Actions › Add missing defaults restores them with these options.
- Settings has four pages: Views, Actions, Repositories and General (the GitHub and Jira setup pages still show while their CLI is missing). Repositories holds the name formats (formerly Worktrees), each repository and the Jira projects; General holds Keyboard shortcuts and Refresh now with the GitHub quota. Every setting keeps its value. Restore defaults is now **Add missing defaults**: it never overwrote edited defaults.
- Tern's palette lists only Plotroom: Open, Open item by URL, Message an agent with the selection… and Go to the first agent that needs input. Every other Plotroom command stays in Commands (`.`) with its key, and stays runnable by its action name `plugin.plotroom.<id>` (key binds, `tern ctl plugins run`).
- README.md is a product page (who Plotroom is for, the loop, screenshots, install and first run); the full behavior spec moved, unchanged, to [docs/reference.md](docs/reference.md), ordered by the loop's steps.
- UI text uses only PRODUCT.md's glossary: **Commands** (the `.` menu, its first group **Actions**), **Worktrees**, **Needs attention only**, **Snooze until tomorrow**, **Open** and **Open Git view**, and **Checkout** for the repository's main clone (an action's Runs in reads Worktree / Checkout; the shell lens offers Show in Plotroom, Copy, Open). Commands rows show an action's first line filled for the selected item, or no detail, never `{placeholders}`; the duplicate-agent offer names the action, not a pane; the protocol warning reads "Plotroom on <host> is a different version from this window's". Pickers say what Enter does; the narrow layout's view dropdown no longer repeats the view's name as the title.
- Queue rows show only what decides at the list level: the title, the author once (the mark), the number, the repository only when the view's rows span more than one, and for a Blocked pull request the one thing that blocks it (Conflicts with its base, Changes requested or Checks failing) in place of the review text and the `✓ ok/total` check count. The `@author` and age in the detail line, the labels and the In tab badge left the rows; the preview still shows each, and the Blocked badge no longer repeats its reason on hover.
- Everything you can click looks it, and nothing else does: the preview's actions (Next move such as Re-run failed checks, Retry, Unpin, Unsnooze, Show less, Get started's Dismiss or Close and its action lines, the shortcut list's Close, a confirm's Keep and Remove, the Copy icons) are ringed buttons sized to their label, and what opens something (a check with a page, a linked pull request or issue, the head's Open icon, a setup guide) is a link in the accent color, underlined under the pointer. Checks without a page, reviewers, Jira's linked issues and the shortcut list's keys stay plain.
- Every preview (pull request, GitHub issue, Jira issue, worktree, agent, Now row) shows its parts in one order: head, title, next move, status (stage, **Blocked by**, the agent's outcome and check), worktree or agent, description, facts, linked items, reviewers, checks ([docs/reference.md › Finer points › Preview](docs/reference.md#finer-points)). Linked items read **Linked issues** or **Linked pull requests** everywhere; Reviewers, Checks and linked items all say `Loading …`, `Could not load …` with Retry (a failed detail load no longer hides Reviewers), or `No …` when empty. A pull request lists the issues it closes. Someone else's pull request that asks for your review leads with its author and size. The merge state shows what the search said until the details load, reads **Unknown** (not a lasting "Checking…") while GitHub has not computed it, and is gone from merged and closed pull requests. Now's Snoozed fact shows the snooze's real end. The preview's In tab chip is gone (the worktree card's Go to tab says it).
- Agent placement: an agent Beside the queue, or joining a worktree's open tab, halves that tab's largest pane along its longer side instead of halving the queue (or opening a tab and moving), so the queue keeps its first half: in a 2200×1000 window five agents beside the queue are each at least 270×470 px, where the queue and the newest two used to end 94 px wide. An agent beside the queue no longer opens a tab, even briefly.
- The default **Check** acts as the run's GitHub login (`gh auth token --user {github.user}` for `gh` and networked `git`, as the other defaults do), so it reads private repositories when another `gh` account is active, and keeps scratch files outside the repository, leaving the worktree as it found it (`git status --porcelain` empty, or reporting what it could not clean) so the next fix round does not stop at a dirty tree.
- Draft review is now a focused workspace: a clickable findings navigator, one readable diff and Markdown feedback pane, verdict and Send controls at the top, and explicit Edit/Done controls

### Removed
- The queue's bottom bar (the `Sort: …` line and the action buttons) in every view: actions are their keys and Commands rows, a sort change is announced by its **Sorted:** toast (Settings › Views › Sort by shows the current order), GitHub's rate-limit pause shows in the header as **Paused by GitHub until HH:MM:SS**, and Remove on a locked or missing worktree toasts why.
- The Inbox list (its notifications and Mark all notifications read… are in Now), the Needs attention only filter with its `n` one-key shortcut, the pane title's `N new` and the status bar's `N need attention` and `N agents need input` segments (one `N need you` count replaces them; the toast for an agent that starts waiting stays).
- Commands: Add label… and Remove label…, Re-run all jobs… and Cancel running workflow…, Send a Browser page element to an agent…, and the Jira transition… picker with its REST client. `PLOTROOM_JIRA_API_TOKEN` is no longer read; an action's Move to status (acli) still moves Jira issues.
- The action field Tell Carly when it finishes and the `plotroom_agents` Carly export. Saved actions that carry it still load; the field is dropped the next time that kind's actions are saved.
- Export and import of views and actions.
- Open floating preview: Enter and Open show the item's page in Tern's Browser beside the queue.

### Fixed
- The sidebar's Agents entry, and the Agents list's field, show an icon (`sparkle`) instead of a blank square: `bot` is not a Tern icon.
- Open item by URL and the shell lens's Show in Plotroom wait up to 10 s for an open Plotroom block that has not shown yet (one an earlier request just launched, or one still connecting to its host), as for a block they launch, instead of failing at once with "Plotroom did not start in time".
