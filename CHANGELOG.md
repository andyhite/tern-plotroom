# Changelog

All notable changes to Plotroom are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The version in `plugin/plugin.toml` is the release; the protocol a window and its hosts speak is separate (see [docs/reference.md › Setup](docs/reference.md#setup), Remote hosts).

## [Unreleased]

### Added

- SECURITY.md says how to report a vulnerability privately and what is in scope; the README's More list links it and AGENTS.md as the contributor guide (tern-plotroom#tcrg).
- The Draft review shows a **Retry** button (also `r`) beside a diff problem: it reads the pull request and the diff again for the same proposal, busy while it runs, keeping every comment's edited text and keep or drop choice, instead of leaving the comments without their lines until the agent proposes again or the block is reopened (tern-plotroom#70mt).
- Get started shows an "Update git to 2.36 or newer" line (with git's download page) while `git --version` reads older than 2.36, whose `git worktree list -z` the Worktrees list and the worktree card need; before, an older git left both empty with no explanation. README and the reference now also list `acli jira auth login` and `ssh` (for SSH-alias remotes) among the prerequisites (tern-plotroom#79zg).

### Changed

- Settings › Actions with neither `gh` nor `acli` installed shows "Install gh or acli first: see Settings › GitHub and Settings › Jira." with a Setup guide button for each, instead of an empty sheet (tern-plotroom#b789).

### Fixed

- A view's name is refused over 120 characters (it was not limited), and an action's or view's name is counted in characters, not bytes: 70 CJK characters are no longer refused as "at most 120 characters". The sidebar, the title, the Delete view confirm and Settings' view rows show a view's name on one line, cut to 60 characters.
- Deleting a pull request action now reports a failed cleanup of issue actions' `next` on its Delete row instead of dropping the error (tern-plotroom#ma6s).
- Settings › General: Reset on a shortcut whose default another action now holds (Commands' `.` bound to another action) says "Already the shortcut of <action>." instead of doing nothing and showing no reason (tern-plotroom#qxz5).
- Tern's search field is shown again at the top of Settings (a stale "too few settings" rule hid it), so a shortcut or setting is found by typing instead of scrolling the General page's 21 shortcut rows and the open views and actions (tern-plotroom#67ks).
- Typing in a Settings field, and every other Settings key press or click, no longer rebuilds the whole page and rereads every saved store several times: a render builds the page once and the keys and clicks after it use that build, and a render reads each store once (tern-plotroom#m7bj).
- A Jira issue whose comment list acli returned cut (fewer comments than `fields.comment.total`) is no longer read as complete: Now keeps an assigned issue instead of dropping it as "yours" on a stale newest comment, and a Summary gets no recent comments rather than old ones as the newest (tern-plotroom#an4x).
- The preview head's Open is a quiet icon button (with the Enter keycap) like Copy link beside it, instead of a globe icon wearing the link role, which drew no cue that it opens something (tern-plotroom#yyvx).
- Now's notification badges use each reason's tone (a security alert is error; CI, Comment, Subscribed and the like are muted) instead of the your-turn accent for every notification (tern-plotroom#2c3b).
- Pasted or inserted text in a search field or prompt editor is capped at 200,000 bytes (cut at a character boundary), so a multi-megabyte paste no longer freezes the host or holds 50 full undo copies (tern-plotroom#9arm).
- A render of the queue now reads the saved shortcuts (kv `keys`) once instead of 5 to 8 times, and a key press once instead of up to three, so every part of one render sees the same bindings and a 1000-item queue spends less per render and keystroke (tern-plotroom#b4wr).
- The Get started checklist's checkout lines are keyed by the repository name with `/` and `.` escaped (as picker ids are), so a repository such as `owner/foo.js` no longer yields an ambiguous dotted key path (tern-plotroom#qdk0).
- A search page that fails with a GitHub error other than SSO authorization (a timeout, `RESOURCE_LIMITS_EXCEEDED`, "Something went wrong while executing your query") is now asked again once for the same cursor with 25 items instead of 100, and the rest of that search keeps asking 25 (up to the same 1,000-item cap), so a large account's view loads instead of ending with "gh exited with status 1" (tern-plotroom#0jkc).
- The sidebar's view counts are counted once per list, triage or agent change and minute and reused by later renders, instead of walking every view's items on each cursor move and tick (tern-plotroom#ewqc).
- A link in a Jira description or comment is kept only when its target is an `http://` or `https://` URL of at most 2000 bytes with no whitespace or control bytes, and its parentheses are percent-encoded, so a crafted target can no longer close the markdown link or pass `javascript:`, `file:` or `data:` on; any other target leaves the link text plain, and a smart link to one draws nothing (tern-plotroom#6xb8).
- A deleted or renamed repository (`gh api graphql`: `Could not resolve to a Repository`) now reads as Repository not visible, an offline machine as **GitHub not reachable** (retried at the next refresh), and a `gh` stopped by a signal as "gh was stopped before it answered", instead of all three reading `gh exited with status …` (tern-plotroom#b4x7).
- An action's Move to status on a Jira issue is now bound to the Jira account and site acli was signed in as when the action started, as assign and comment already were: after `acli jira auth switch` or a login to another site in between, nothing is moved and the toast says the acli account changed, instead of making the transition as the other account (tern-plotroom#w4bw). New rpc op `jira-who`, protocol 55.
- Concurrent GitHub calls for one login on a cold token cache now share one `gh auth token` read instead of spawning one each (several keychain prompts at once on macOS); when that read fails every waiting call gets the problem, nothing is cached, and the next call reads again (tern-plotroom#7de0).
- When the saved agent links (kv `agent-links`) cannot be read, every pane's status line now shows **Agent links unreadable** and the plugin log gets one warning, instead of agent status, chain steps, outcome checks and the Draft review silently stopping. The store is still never written over; it clears on its own once it reads again (tern-plotroom#d4g6).
- The merge sweep keeps at most 4 `outcome` requests in flight (the host keeps only 8 answers on screen) and sends the rest, oldest first, as answers arrive, so no undecided checked run waits for the next 10-minute sweep (tern-plotroom#vptz).
- A program that still cannot be started after a login shell probe no longer starts another login shell on every spawn: the shell is probed again at most once a minute (Retry lifts the wait), so a missing `acli` or `git` costs one probe instead of up to 5 seconds per call (tern-plotroom#pcxt).
- Open item by URL, pasting a URL and the shell lens accept a GitHub pull request or issue URL with a sub-page (`/files`, `/commits/<sha>`, `/checks`) and `http://` or `www.github.com` forms, so URLs copied from a pull request's tabs open the item instead of "not a pull request or issue" (tern-plotroom#q82c).
- An agent set to open beside the queue now starts in a tab of its own when the Plotroom pane closed while a new worktree's setup ran, instead of splitting whatever pane was focused or failing in the timer (tern-plotroom#7zhp).
- A Draft review whose repository has a `.` or `..` part (`../x`) is refused by `plotroom_propose_review` and by the Draft review block, and every GitHub read of one pull request or issue (its metadata, checks, details, Evidence, linked pull requests) refuses a repository other than `owner/name`, a number that is not a whole positive number, or a Jira key with anything else in it, before gh runs, so no such value can redirect a request made with your gh token (tern-plotroom#a0f9).
- A line in an item's description or comment that reads `BEGIN ITEM` or `END ITEM` is wrapped in parentheses in the Summary prompt, so tracker text can no longer close the untrusted block early (tern-plotroom#jqn1).
- A run's whole folder, its Draft review included, is now deleted when the run leaves the run log (the review file was kept for ever), and a run folder that no log entry names is deleted 30 days after its run began, when a Plotroom block starts on that host, so `runs/` no longer grows without bound (tern-plotroom#7w4x).
- Closing a Plotroom block while the window waits for its host (a worktree being prepared, a chain step's next action, a menu) now ends those requests at once with one "Plotroom: the block closed" toast, and a chain step counts it as a failed start, instead of polling for up to 11 minutes and then toasting "the block's host did not answer" (tern-plotroom#b34x).
- An answer to the window, the command palette's published rows and the Draft review's message can no longer outgrow the window's 64000-character read: the repository lists and the palette's queue actions and commands are cut like the other pickers' rows, an answer still too large says so instead of failing to be read, and a Draft review message too large to send goes straight to Copy instead of waiting out Send (tern-plotroom#qk6y).
- A `gh auth switch` is now seen within a poll (the list of signed-in logins is read again when it is 20 s old, was 10 min), and when the active account changes, or none is active any more, a view with no login of its own drops the old account's list, checks, Likely flaky marks and sign-in problem and searches again as the new account, so Ready for review, Review suggestions and `{github.user}` in a new branch name no longer use the previous login (tern-plotroom#78qv).
- A removed worktree's note is dropped in every other Plotroom block on the host even when the block that asked was closed during the removal, so their Worktree badge, Open Git and Remove no longer linger (tern-plotroom#cpr3).
- Every `acli` call now runs with `NO_COLOR=1` as `gh` does, and the message of an acli failure has its colour sequences cut and passes through the same control-character cleaning as other tracker text, so a coloured or control-byte error no longer shows escape bytes in a toast or problem row (tern-plotroom#v3kx).
- The `{failures}` prompt block stays within its byte cap: a failing check's name and link are cut to 120 and 200 characters, and a check whose excerpt does not fit its share of the cap now shows a `… N lines` marker instead of only its heading (tern-plotroom#3gn3).
- A plan that the palette asks while a Stop agent or Remove worktree confirm (or a Board removal confirm) is open now replaces it, as a message already did, so cancelling the plan no longer brings the older confirm back (tern-plotroom#gg2f).
- A confirmation with a wrong, replaced or repeated token no longer cancels the plan waiting for its confirmation, and a plan that throws now shows its error instead of vanishing (tern-plotroom#14t6).
- A worktrees directory that is a symlink (macOS `/tmp` and `/var` are) or holds `.` or `..` segments no longer hides the worktree Plotroom made there: git lists a worktree under its real path, so the worktree at an item's folder on another branch was not recognised and the open ended in "already exists and is not the worktree of …". Plotroom now resolves the directory to its real path before it builds a worktree's folder (tern-plotroom#q9xp).
- A search that lands after the view or account changed is kept for its own view instead of discarded, so switching A → B → A quickly shows A's list at once and does not spend its GraphQL points twice (tern-plotroom#3awd).
- A checkout found from a linked worktree is saved as the main worktree git lists first, also for a repository whose git directory is not `<main>/.git` (`--separate-git-dir`) (tern-plotroom#f77a).
- Remove finished worktrees asks GitHub or Jira about each pull request or issue again just before removing its worktree, instead of trusting the verdict of an old Find finished worktrees: a pull request or issue reopened since is kept, loses its Merged or Closed mark, and the toast says how many were kept for that.
- Oldest waiting puts an item whose creation date could not be read last instead of first, and a view applies only a sort its kind offers.
- Worktree on an issue whose folder holds a detached worktree now says the worktree is detached instead of reporting it on a branch it is not on and writing git config for that branch.
- A pull request into a base branch such as `release/1.0+rc` or `user@x/topic`, or a repository whose remote is named `team/fork`, now gets its Draft review diff and its pre-merge of the base instead of an unexplained refusal: pull request metadata, the review diff and the pre-merge accept one set of branch and remote names (`+` and `@` allowed; `..`, `//`, a trailing `/` or `.`, and `.lock` refused). A refusal names the value (the base branch, or the remote) and says when the pull request names no base branch.
- A worktree whose `git config` writes fail (the branch's upstream, or the note that links it to its item) is no longer left silently without them: each write is tried once more after 0.3 s (another window's `git config` holds `.git/config.lock` for a moment), and one that still fails shows an error toast **Worktree ready for …, but not fully set up** with git's reason.
- A pull request from a deleted fork by an app account (an author such as `dependabot[bot]`) can be checked out: the author is used as the fork's branch prefix only when it is a plain login, otherwise `fork`, instead of building a branch name git refuses and ending in "Could not inspect branch".
- The signature behind New and Changed is now a true FNV-1a hash: its multiply used to pass 2^53 and lose low bits, so two different item states could share a signature far more often than they should and a change could go unmarked. Every item seen before this release shows as Changed once, because its stored signature is recomputed.
- The `?` shortcut list now has rows for Move left and Move right (the Board's columns), Find finished worktrees and Remove worktree, so a bound `h`, `l`, `u` or `d` can be looked up; a test fails when an action a key can be bound to has no row.
- An item is marked seen only after the selection has rested on its preview for a second (the Summary's rest), not the moment you arrow onto it: an assigned issue you only scrolled past stays New and stays in Now.
- Titles, authors, labels, assignees and check names from GitHub, and summaries, reporters, statuses, types, priorities and labels from Jira, are cleaned and cut once, when they are read (a title to 256 characters, the rest to 100): C1 controls and Unicode's bidi controls (such as U+202E, which reverses the text after it) are dropped along with the control characters already dropped, instead of reaching rows, toasts, confirms and prompts as received. Text agents report and error text show those characters as spaces.
- A Draft review of a pull request whose diff is too large now says "The diff is too large to show" and keeps every comment, instead of reading a diff Tern cut at its 16 MiB output cap as if whole and calling every comment past the cut Not on a changed line. Git counts the changed lines first (`git diff --shortstat`), so a diff of over about a million changed lines is never written, and the diff is read without textconv filters, as GitHub's is.
- A view whose query returns items of the other kind (`is:issue` in a pull request view, `is:pr` in an Issues view) lists the items of its own kind and leaves the rest out of its count, instead of failing the whole view with "the search returned an item that is not a pull request".
- Plotroom's pre-merge of the base (Merge the base first, the default Watch) now also skips a pull request another login wrote: the merge commit and lockfile tools (`bundle lock`, `pnpm install --lockfile-only`, `poetry lock`, …) that can run repository files only run in a worktree of a pull request the run's own login wrote, as before never on a fork's. The agent resolves the conflict itself.
- Plotroom merges a conflicting pull request's base into its worktree before an agent starts only for an action with Settings › Actions › **Merge the base first** on (the default Watch; a Watch saved earlier keeps it), not whenever the prompt contains the word "conflict": a typed prompt, or an action that only mentions conflicts, no longer gets a merge commit and regenerated lockfiles in your worktree. A toast now says what was merged and regenerated, what conflicts are left for the agent, or why the base could not be merged.
- The `?` shortcut list draws an upper-case key as Shift and its letter, so `g`/`G` and `z`/`Z` are no longer the same keycap, and hints name it (`press Shift+Z to show them`).
- The checks table now heads Passed and Skipped each with its own muted `Passed N` / `Skipped N` line inside the folded section, so the two tables no longer read as one list.
- A locked or missing worktree's card no longer shows a greyed Remove button; Remove is offered only when it applies, and the Locked fact says why.
- Now asks `acli` about at most four assigned Jira issues at a time, instead of starting one or two `acli` processes for every assigned issue at once on each read.
- A failing check's log now reads `TypeError: x`, `ERROR: x`, `[ERROR] x`, `Exception in thread …`, `java.lang.NullPointerException` and ESLint's `✖` as error lines, so the `{failures}` excerpt and the preview's first error line show the cause instead of the last 30 lines.
- Settings › Repositories › Remove now says so when a saved store (checkouts, branch formats, setup commands) cannot be read, instead of reporting success while the repository stays listed.
- Now keeps being read when the active view's query is rejected or names a repository your login cannot see, and when the block has no active view: it is read again at the poll interval, so the pane title count and the status line's `N need you` stay current instead of freezing until Refresh. A sign-in failure or a missing CLI still holds it.
- A snooze ends when the item changes (checks going red, a review, a push, a comment since you snoozed it), not only at 08:00 tomorrow: the item is listed, counted and in Now again as Changed. The Snooze toast says "until tomorrow, or until it changes". Snoozes saved before this still run to their time.
- A request the host rejects (an unknown op, a malformed repository, number, URL or field, or an error while answering) is answered with the reason at once, instead of being dropped and leaving the window's card busy until its 30 s to 11 min timer ended in "the block's host did not answer". Only a request with no valid id is still dropped.
- A run that failed, or whose agent program exited, with no end-of-run report is no longer silent: one error toast names the item (`o/r#5: agent failed`), and after the agent exits its item stays Needs you in Now with an Agent failed or Agent exited badge, and its action offered again as the Next move, until a newer run replaces it.
- Remotes at `ssh.github.com` (GitHub's SSH over port 443), an SSH alias that `ssh -G` resolves to it, and ssh remotes with an Enterprise-managed user (`org-123@github.com:o/r`) are recognised as GitHub, so Worktree, Draft PR and Draft review diffs work for those checkouts.
- The Draft review reads a pull request's diff with up to 120 s, not 10 s, and fetches the pull request's head only when git says the head commit is missing; a timeout or another failure (such as no merge base) is shown at once instead of after a pointless fetch and a second try.
- A pull request whose base branch has characters Plotroom does not accept in a branch name (as its head branch already was) is refused by Worktree and agents, so a base branch named like shell syntax never reaches an agent prompt's `{base}`.
- A worktree removal's confirm (the card's, the Worktrees list's, and Remove finished worktrees) now warns when files or folders git ignores (`.env`, local config, a built `node_modules`) will be deleted with the worktree, with their count and the first names: `git worktree remove` deletes them without asking and the Clean badge never counted them. Remove is offered once that is read; it is a warning, not a refusal.
- Remove worktree, the Worktrees list's Remove and Remove finished worktrees refuse a worktree a tab works in or a live agent runs in, instead of deleting the folder under it (the confirm used to only warn about a tab). Remove finished worktrees leaves such rows out and says how many it kept.
- Approve and Request changes are bound to the head commit the confirm shows ("Approves commit abc1234; a push since refuses it"): a pull request pushed to since the plan is refused and nothing is posted, as Merge already was. Both refuse while GitHub has not said the head.
- Plotroom's own `git fetch`, `git ls-remote` and `git push` run as the view's gh login (a draft pull request's push as the login its confirm names) over an `https://github.com/…` remote: git gets that login's token through `gh auth git-credential` instead of your credential helper, which answered with gh's active account. A worktree of a private pull request on a view of a non-active login no longer fails with "repository not found". SSH remotes are unchanged.
- An Unchecked outcome no longer asks GitHub every minute forever: a run with no GitHub repository or login (a Jira issue with no code repository, a login that could not be read) is recorded Unchecked once without asking, and other Unchecked runs are checked again every minute in their first hour, every 5 minutes up to 6 hours, every 30 minutes after, and not at all once a day old with their agent exited.

### Changed
- **Close issue…** asks how the issue closes, Completed or Not planned, and for an optional closing comment before the confirmation, which names the reason and shows the comment; GitHub records the reason and posts the comment with the close, instead of always closing as completed with no explanation. Hosts speak rpc protocol 51 (act's `issue-close` takes `reason` and `text`).
- A draft pull request's confirm no longer resolves the repository again from scratch (`git rev-parse` twice, `git remote`, `git remote get-url --all` per remote, `ssh -G` per SSH alias) for its commit and its push: the checkout and remote its preview found less than 5 s earlier are reused, so the preview and the confirm read each remote once. The branch, its head, the base and whether it needs pushing are still read again at the confirm (tern-plotroom#bwdf).

### Added
- Copy usage report can now read PRODUCT.md's metrics 4, 5 and 7: **First use** gives the time from Plotroom's first start (kv `usage`'s `since` is now that, not the first count) to the first agent run, and whether Settings was opened before it (every way Settings opens counts as `queue:settings`, each count now keeps its first use); **Default actions Verified: x of y (z%)** counts only runs of an unedited shipped action that name an outcome (a run now records `default`; an edited action's runs are listed apart as `Review (custom)`); **Days used per week** gives, per ISO week (`2026-W46`), the days Plotroom was used on, so a design partner's pasted report shows whether they used it each week. A store from before this has no first uses or weeks and reports them as unknown.
- An item's preview keeps its last run's outcome and check after its agent exits or its pane closes: with no live agent, the Status section shows a **Last run** fact (action, age, how it ended) from the run log, with the run's Outcome, Check, Findings, Report, Reason and Blocker, so a Not verified or failed run no longer looks like one never run (tern-plotroom#fa1j).
- Comment…, Approve…, Request changes…, Type a prompt… and a draft pull request's description are written in a multi-line editor in the Plotroom block (the Compose overlay: Enter adds a line, ⌘↵ goes on, Esc cancels) instead of a one-line prompt, so a comment or a brief can hold paragraphs, lists and code; the comment's confirm shows every line, editing a description no longer replaces it with one line, and a comment whose plan is refused opens the editor again with your text. Needs the block's host on this version (rpc protocol 52).
- Checks lens: `gh pr checks` in a shell pane shows its checks as a table (Check; Status as a dot in the preview's check colours and Pass, Fail, Pending or Skipped; Took; Link), the last table under `--watch`. A URL gh cut to the terminal's width gets no link, and output with no checks table stays raw. Shell panes start with `GLAMOUR_STYLE=dark` when it is unset, so gh's background-colour query no longer makes Tern show gh's output raw.
- The pull request and issue previews are pages: a card heads them (the kind's icon, the title, `#N · repository · GitHub` or the Jira key, and at its end the state, the Next move, Copy link and Open), then a strip of stats (a pull request's Checks, Changes with its file count, Comments and Age; an issue's Comments, Age and Linked) replaces the diff meter and those facts. A pull request's preview then has tabs, **Overview**, **Checks N**, **Threads N** and **Reviewers N**, and draws only the active one; Tab and Shift+Tab (or a click, or the key footer's segs) switch them, and ← moves to the views (→, Tab, Enter or Esc back). Unpin and Unsnooze sit under the Stage.
- Draft review: the navigator and the selected item sit in a split you resize by dragging its handle (stacked in panes narrower than 100 columns), and the block keeps the share you dragged, across restarts. The selected item is a card headed by the finding's path with its lines beside it and Keep/Drop and Edit at the head's end; the verdict is one joined control with the chosen one on; a suggestion shows as a diff of the lines it replaces (or as code when it is on the old side or off the diff) instead of a Markdown fence.
- Alt-click a GitHub pull request or issue link in any pane to show it in Plotroom, as the shell lens's Show in Plotroom does (fetched, then pinned). It applies only while the window has a Plotroom block; a plain click, any other page, or a window without one opens the link as before.
- Shell lens after `git push`: when GitHub prints its "Create a pull request" line for a newly pushed branch, the output shows **Create pull request** (GitHub's `/pull/new/<branch>` page) and **Show in Plotroom**, which looks up the branch's pull request when clicked and shows it, or says there is none yet.
- Both Plotroom blocks open in Tern's sans face (`font = "sans"`), and the Draft review drops its own CSS font rules: people's text is in the UI face, while ids, refs, branches, SHAs (now also the Draft review's head and moved-head SHAs), paths and the agent clock stay mono. The queue's view name takes Tern's `title` token, and the agent clock is `mono` instead of `num`.
- Worktree tab names survive a plugin reload: a worktree tab's `#123 title` is kept in kv `tab-labels` (the newest 50) and read at load, so restored tabs keep it. A closed tab's name is dropped when a pane or tab closes; a malformed store is never written over.
- The queue refreshes as soon as `git push`, or a `gh pr`, `gh issue` or `gh run` command, succeeds in any shell pane on the block's host, instead of waiting for its timer; GitHub's rate-limit cooldown still holds. Failed commands and other lines change nothing.
- A tab Plotroom opened for a worktree turns blue (your turn's colour) while its agent waits for input, and loses the tint when the agent works or finishes. A colour you set on the tab is never cleared or overwritten.
- Settings' on/off rows (Now's reasons, team review requests and accounts; Summaries) are Tern's native switches instead of On/Off segments; Enter on the row flips them. Each Settings page's nav entry counts what on it differs from the defaults: Now's switches and views (Views), actions (Actions), name formats, checkouts and branch formats (Repositories), shortcuts, action keys and the Summary settings (General).
- Preview checks by state: Failing, Running and Queued, each headed with its count, then Passed and Skipped in one fold that starts folded ("Passed 12 · Skipped 1"). Each check shows its CI (workflow, app or status host) and how long it ran or has been running ("45s", "6m 24s", "1h 05m"); required ones say Required. While a check is unfinished, the previewed pull request's checks are read again every 30 s, until the selection moves or nothing is pending. This replaces the Required and Optional groups.
- Preview checks as native tables: each group (Failing, Running, Queued; Passed and Skipped in their fold) is a table with Check (a dot in the status's colour, then Required, Likely flaky or Ignored), Workflow and Took columns. A click on a check opens its page, and right-clicking it offers Open, **Ignore in this repo…** (a failing check: the same confirm as Ignore this check…, for that check) and Copy row. A failing check's excerpt is code under its first error line, never folded, that line marked, its first 12 lines shown until "N more lines". Opening a check from the preview works again: the window looked for check rows where the groups no longer put them.
- Plotroom's omp extension (`plugin/omp/plotroom.ts`): every agent Plotroom starts runs as `omp -e <plugin folder>/omp/plotroom.ts` (with its action's `--model`), a run id and Plotroom's data directory in its environment, and gets the tool `plotroom_propose_review`, which checks a proposed pull request review and writes it to `runs/<run id>/review.json` in Plotroom's data directory for the Draft review block. Agents now always start as omp, not Tern's agent command; when the extension is not in the plugin folder on the block's host, the agent starts as before and a toast says why.
- Draft review block: when an agent Plotroom started ends a turn with a new Draft review, a second block (Draft review) opens beside it with the review on the pull request's diff: the summary and verdict at the top, one card per comment grouped by file with the lines around it, and comments off the diff listed apart (they cannot be kept). `j`/`k`, Space (keep or drop), `e` (edit), `1`/`2`/`3` (verdict) and ⌘↵ (send) are shown beside their controls. **Send to agent** hands the agent your kept comments as edited, the dropped ids, the verdict, the summary and an optional line of instructions; nothing is posted by the block. A head that moved since the review is said, and a gone agent gets **Copy**. Hosts speak rpc protocol 46 (op `review`).
- Settings › General › Draft review › **Draft review opens**: **Beside the agent** (the default, as before) or **Over the agent's tab**, a Tern glimpse over the whole tab that leaves the agent's pane its size and closes at the next click outside it; a turn end while the agent's tab is not shown opens nothing and says so. **Show Draft review** (Commands › Actions, and the Agents list) focuses the run's open Draft review or opens it again. Hosts speak rpc protocol 47 (review's `glimpse`, agent-status's `review`).
- The key footer is Tern's status strip in the block's dock: it lists every key that works now instead of at most five, a narrow pane drops the least used first, and a click on a key runs what the key runs.
- Key footer: a line under the queue lists the keys that work for what is selected now, each with what it does: Commands (`.`) and Shortcut list first, then the Next move, then the most used. A key with nothing bound is not listed, and a saved action's key shows that action only where it beats the built-in key. The preview's Unsnooze button shows the Snooze until tomorrow key, which ends a snooze.

Hosts announce protocol 44 (act's `check`).

The preview's checks show the mark and why; a row whose every failing check is marked says **Checks failing (likely flaky)** (never when the PR has more checks than are loaded). Hosts announce protocol 42 (the `models` request and the actions' `effort` field).

The agent's prompt ends with a `<merge>` block listing what was done and the files still conflicted. Hosts announce protocol 41 (the worktree request's `premerge`).
- Commands › GitHub - PR › **Push empty commit…**: for an open pull request whose own branch is up to date with its base and free of conflicts (never a fork's branch), a confirmed plan (Cancel first, naming the account, branch and head SHA) gives the branch a new head so its checks run again, through GitHub's git database API with no checkout: a commit with the head's tree and the head as parent, then the branch moved to it without force. A branch that moved since the plan gets nothing pushed and "The branch moved; refresh and try again."

A pull request whose review of yours was dismissed is Review requested in Now (one more search per login, of open pull requests you reviewed) and its Next move is Review. Both are read from GitHub on every refresh (your latest review and its commit); nothing is stored.

Cached per machine in kv `summaries` (the newest 200) by the item and its head commit or update time; Settings › General › Summary turns them off. The detail load now also reads a pull request's first 30 changed files and the 5 newest comments of a pull request or issue. Hosts announce protocol 45 (the `models` request for `summary:model`).
- **Next in Now**: a new queue action (no default key; the one-key set binds `n`; also Commands › Now) shows Now and selects its most urgent item, then each next one in Now's ranking. Now's heading reads `N left` at rest and `n of N` while walking; a hand move or a change of the list stops the walk, and the next press resumes from the selected item.
- A working agent shows how long it has worked (`m:ss`) on its Agents row, its item's Now row and the previews, and, once its action has 5 finished runs in the run log, a thin bar estimated from their median duration (it eases toward 90% at the median and is never full before the run ends). The view is drawn again once a second while a clock shows. Hosts announce protocol 39 (agent-status's optional `since` and `expected`).
- Failing checks' logs: for each failing GitHub Actions check (at most 5), Plotroom reads `gh run view <run> --log-failed --job <job>` once per check and head commit, keeps 12 lines before and 3 after each error line (else the last 30), at most 120 lines per job, gaps marked `… N lines`, CI markers stripped, and finds up to 5 `path:line` mentions of the pull request's changed files. The preview's Checks section shows each failing check's first error line, with its excerpt under it. Hosts announce protocol 40 (the worktree request's optional `failures` field).
- Arrival ring: when a refresh moves an item into Needs you or Blocked from another stage, its queue row is ringed in that stage's colour (accent, red) for about 1.4 s, then fades; a move into Ready to merge rings green, and an agent that starts needing you rings its row too. Not for a change you made with an item command in that block; under reduced motion the row is tinted instead. New and Changed are unchanged.

A block host without that overlay starts no agent there. The rpc protocol is 50 (`fork`).

One that still requires a review or has changes requested does not.

- Removing a detached worktree whose HEAD holds commits no branch, tag or remote reaches is refused (the confirm says to create a branch first) instead of deleting the only copy of those commits.
- Draft review, Beside the agent: a turn end of an agent in a background tab opens the Draft review split to the right of the agent's own pane, in the agent's tab, without switching tabs or taking focus; it opened beside whatever pane was focused, in the tab shown. Show Draft review still opens it focused.

- The sidebar's Agents entry, and the Agents list's field, show an icon (`sparkle`) instead of a blank square: `bot` is not a Tern icon.
- The Draft review's Edit buttons and the agent review's Edit note (`pen`), the status line's paused and version-mismatch warnings (`warn`), and the Board fold's button (`chev`, `chev-r`) show an icon instead of a blank square: `pencil`, `warning`, `chevron-down` and `chevron-right` are not Tern icons.

- A gh login's repository list that a failed page cut short now says so in an error toast and is no longer kept for 10 minutes as if whole: opening the list again asks GitHub again.

- Settings › General › Use one-key shortcuts now names every key it binds, `h`, `l` and `x` included.
- A Draft review comment on a file whose path holds a space is placed on the diff and can be kept, instead of showing as Not on a changed line: the tab git ends such a diff header with is no longer read as part of the path.

Your own is the run's login, or gh's active one when the block has none.

- Merging the base before conflicts no longer runs in a fork PR's worktree: no `git merge` or commit (the fork's git hooks could run) and no lockfile tool (`bundle lock`, `pnpm`, `uv`/`poetry` can run the fork's code). Its agent resolves the conflict itself.

- `plotroom_propose_review` (its description and its answer) now tells the agent to call `plotroom_report` with attention needs-human before ending its turn, instead of ending it at once, so a Review run waiting on its Draft review shows under **Needs you** instead of **No report**.
- Bare-repository layouts (`repo/.bare` plus a linked worktree you work in): Worktrees no longer lists your saved checkout, Remove worktree refuses it ("That is the checkout; Plotroom never removes it.") instead of running `git worktree remove` on it, and Worktree on a pull request whose head branch it has checked out says so instead of reusing your checkout as the PR's worktree.

- Likely flaky counts only push runs on the base branch: a pull request from a fork's branch named like the base (a fork's `main`) no longer counts as the base's history, so its own failures there cannot mark its failing check Likely flaky.

Saved actions keep their own text.

The ticket comment, the transition and marking the PR ready still wait for your approval.

A report that names no new commit still starts a fix round.
